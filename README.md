# paravg
PARallelized AVeraGer: Efficiently compute averages at scale

Note that the folder `tests` is ignored to reduce the size of the repo,
but it contains files generated by the `number-generator`.
For my own testing, I renamed these `[count]-[expected average]-[desc].txt`.

## Results

On my machine, `paravg`'s performance was within margin or error
(albeit on the slower end) of `simpleavg`'s, with minimal differences
between different thread counts. As expected, larger chunk sizes
offered slightly better performance, up to a certain point.

I believe these results are primarily due to the fact that reading
couldn't be efficiently parallelized, forming a bottleneck compared
to the relatively lightweight tasks of addition and division.

Update: on extremely large files (e.g. 7.2GB), the parallelized version
offers a measurable performance boost.
